# CSV 빠른 검색기

몇 GB짜리 CSV를 SQLite 또는 DuckDB로 가져와서 빠르게 검색하고, 필요한 줄만 CSV로 저장하는 프로그램입니다.

## 실행 파일(exe) 만들기 — Windows

1. Python 3.10 이상을 설치합니다 (설치할 때 "Add Python to PATH" 체크). 이건 exe를 **만드는 PC에서만** 필요합니다.
2. 이 폴더에서 `build.bat`을 더블클릭합니다.
3. 1~3분 뒤 `dist\CsvFastSearch.exe`가 생깁니다. 이 파일 하나만 다른 PC에 복사해서 쓰면 됩니다 (설치 불필요).

Python 설치가 번거로우면 이 폴더를 GitHub 저장소에 올리세요. `.github/workflows/build-windows.yml` 덕분에
Actions 탭에서 exe가 자동으로 만들어집니다.

## 사용법

1. **Import CSV…** → 파일 선택. 인코딩(UTF-8/CP949 등)과 구분자는 자동 감지되고, 미리보기로 확인할 수 있습니다.
2. **주로 어떻게 검색하는지** 고르면 프로그램이 엔진을 추천합니다. 직접 바꿔도 됩니다.
3. 가져오기가 끝나면 DB 파일(.sqlite / .duckdb)이 생깁니다. 다음부터는 **Open database…**로 바로 엽니다.
4. **Search in**에서 검색 범위를 고릅니다.
   - `[Query]` (기본값): 아래의 검색식을 씁니다.
   - `[All columns]` 또는 컬럼 이름: 검색어를 글자 그대로 찾습니다. **Match**에서 Contains / Equals / Starts with / Regex 선택.
   - `[SQL WHERE]`: SQL 조건을 직접 씁니다.
5. 검색창 아래에 검색식을 **어떻게 해석했는지**("Reads as: …")와 **어떤 방법으로 찾는지**(인덱스 / 스캔)가 표시됩니다.
6. **Save all results as CSV…** — 화면의 500줄이 아니라 조건에 맞는 모든 줄을 저장합니다.

그 밖에: 줄을 더블클릭하면 전체 내용을 세로로 보여주고, Ctrl+C로 선택한 줄을 엑셀에 붙여넣을 수 있습니다.
exe 위에 CSV나 DB 파일을 끌어다 놓아도 열립니다.

## 검색식 ([Query])

| 쓰는 법 | 의미 |
|---|---|
| `word` 또는 `"some text"` | 아무 컬럼에나 그 글자가 들어 있음 |
| `[컬럼]:"text"` 또는 `[컬럼]."text"` | 그 컬럼에 글자가 들어 있음 |
| `[컬럼]="text"` | 그 컬럼 값이 정확히 같음 |
| `[컬럼]~"정규식"` | 그 컬럼이 정규식과 일치 |
| `"abc*"` / `"*abc"` / `"a*c"` | abc로 시작 / abc로 끝남 / 와일드카드 |
| `A AND B`, `A B`, `A && B` | 둘 다 |
| `A OR B`, `A \|\| B` | 둘 중 하나 |
| `NOT A` | 제외 |
| `( … )` | 묶기 |

AND가 OR보다 먼저 계산됩니다 (`a OR b AND c` = `a OR (b AND c)`). AND / OR / NOT은 대소문자를 가리지 않습니다.
따옴표는 공백·괄호가 들어간 글자에만 필요하고, 따옴표 안에서 따옴표는 `\"`로 씁니다.
화면의 **?** 버튼을 누르면 전체 문법과 예시가 나옵니다.

예시:

```
( [상품명]."무선" AND "배송완료" ) or "user1*"
[배송상태]="반품" AND NOT [결제수단]:"카드"
[주문일시]:"2025-12*" [지역]:서울
```

## 검색 기록 (History)

검색할 때마다 자동으로 기록됩니다 (결과 개수, DB 파일 포함, 최대 1,000개).

- **History…** 창: 필터로 찾고, 더블클릭하면 다시 검색합니다. 다른 DB에서 한 검색이면 그 DB를 열어서 실행합니다.
- 검색창에서 **↑ / ↓** 키: 현재 DB의 이전 검색을 차례로 불러옵니다.
- 저장 위치: `%APPDATA%\CsvFastSearch\history.json`

## 엔진 고르는 기준

| | SQLite | DuckDB |
|---|---|---|
| 가져오기 속도 | 느림 (FTS까지 만들면 더 느림) | 빠름 |
| DB 용량 | CSV의 약 1.3배, FTS 포함 시 3~4배 | CSV의 약 0.3~0.6배 |
| 키워드 검색 | FTS가 있으면 거의 즉시 | 병렬 스캔으로 빠름 (수 GB에서 보통 1초 안팎) |
| 특정 값 찾기 | 컬럼 인덱스 + 대소문자 구분 시 즉시 | 병렬 스캔으로 빠름 |
| 결과 대량 저장 | 보통 | 빠름 |

## 자동으로 고르는 검색 방법

- **SQLite + FTS**: 3글자 이상 '포함' 검색은 전문검색 인덱스(trigram)로 바로 찾습니다. '일치' 검색은 FTS로 후보를 좁힌 뒤 정확히 비교합니다.
- **SQLite + 컬럼 인덱스**: '일치'·'시작' 검색에서 대소문자 구분을 켜면 인덱스를 씁니다. 인덱스는 "이 컬럼에 인덱스 만들기" 버튼으로 만듭니다.
- **그 외**: 전체 스캔. DuckDB는 모든 CPU 코어로 병렬 스캔합니다.

## SQL 조건 직접 입력 ([SQL WHERE])

테이블 이름은 `data_view`, 컬럼 이름은 큰따옴표, 값은 작은따옴표로 씁니다. 모든 값은 글자로 저장되므로 숫자 비교는 변환이 필요합니다.

- DuckDB: `TRY_CAST("나이" AS INTEGER) > 30 AND "지역" = '서울'`
- SQLite: `CAST("나이" AS INTEGER) > 30 AND "지역" = '서울'`

## 참고

- 칸 수가 헤더와 다른 줄은 SQLite에서는 모자란 칸을 비우고 넘치는 칸은 마지막 컬럼에 합쳐서 보존합니다. DuckDB에서는 넘치는 칸이 잘립니다.
- 서명되지 않은 exe라서 처음 실행할 때 Windows SmartScreen 경고가 나올 수 있습니다 ("추가 정보 → 실행").
